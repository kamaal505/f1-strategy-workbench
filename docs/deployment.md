# Streamlit Community Cloud deployment

The public interface defaults to fail-closed mode; set `F1_STRATEGY_MODE=local` only for private local research. A synthetic demonstration is not authorization for real races and is not a real-race launch. Source subscriptions and FastF1's code licence do not grant public display or redistribution rights. Operator records represent assertions of permission, not a legal determination.

## Prerequisites and setup

1. Obtain applicable rights for every actual source and session, including the complete fitting, tuning and calibration corpus. Prepare server-only authorization records and any authorized model/snapshot artifacts. Do not commit credentials, authorization evidence, private tokens or unauthorized artifacts.
2. Use an operator-controlled GitHub repository, a connected Streamlit Community Cloud account with repository administrator access, branch `main`, Python 3.12 and entrypoint `streamlit_app.py`. The root `uv.lock` and installable `pyproject.toml` are the only dependency specification. Cloud selects uv; confirm its build log shows the locked project and package installed. If the provider no longer installs the project from this configuration, treat that as a deployment prerequisite rather than adding a startup installer.
3. Set server-side `F1_STRATEGY_AUTHORIZATION_FILE` to a private file path. It contains a JSON array of records, each with `source_ids`, `session_ids`, `scopes`, `expires_utc` (UTC ISO timestamp or null), `permission_reference_id`, and `confirmed_utc` (UTC ISO timestamp). Confidential proof stays outside the repository. Each source/session pair and each requested scope must be covered by an unexpired confirmed record. Supported scopes are `source_access`, `snapshot_retention`, `public_display`, `derived_report_download`, `model_server_use`, and `public_asset_distribution`. Model lineage is checked independently of the focal observation; report downloads require permission across all lineage. Revoking or expiring a record disables subsequent returns.
4. Hosted acquisition uses anonymous TracingInsights access; no source login, API key or confirmation environment variables are needed. The parent checks `source_access` and `snapshot_retention` against records for `tracinginsights:YYYY-RR-R` before launching the child and at publication. Workers receive neither credentials nor the authorization-record path. Hosted acquisition is restricted to curated races, without telemetry. Offline replay requires no network.
5. The operator may generate `<root>/public_registry.json` as a JSON array of entries with `session_id`, `snapshot_id`, `model_id`, `driver_number`, `completed_lap`, and optionally a validated `scenario` object. Only `2023-07-R`, `2023-15-R`, `2024-03-R` and clearly labelled synthetic entries are admitted. IDs refer to immutable artifacts beneath the server root, not visitor paths. Each manifest and full lineage must validate, and all required public distribution, display and model-use scopes must be granted before model arrays are loaded. Missing or invalid entries are omitted. A generated synthetic `index.json` in the selected demo root is automatically discovered when its model is available.
6. Run `uv run --locked f1-strategy deployment-check --root <root>`, then inspect the actual Cloud build and test the public URL in a fresh browser. Check an authorized real-race comparison, report download, identity, credential isolation and expiry behavior. An available catalog is not proof of provider installation, permission, public access or successful launch.

## Capacity and persistence

The parent admits one heavy acquisition, comparison or report-rendering child at a time; other requests get `busy`, with no queue. Admission deadlines are 180 seconds for ingestion and 90 seconds for comparison and report rendering, including validation; hosted comparisons default to 200 draws and allow at most 1,000. Request stdin is capped at 256 KiB, captured stdout at 8 MiB and stderr at 1 MiB; report input is limited to 8 MiB and the fixed renderer returns only a relative filename and checksum. Reports render from the sealed saved analysis without loading snapshots or models, and download permission is rechecked for the complete lineage before return. The parent monitors mutable responses, staging, snapshots and hosted reports against 256 MiB every 0.5 seconds; writes can overshoot between observations, so this is not an operating-system disk quota. Workers are terminated and reaped before staging cleanup. Leases protect snapshot readers from eviction. Errors do not return stale or fabricated results.

Streamlit Community Cloud can sleep and cold-start, and its filesystem is ephemeral. Store only appropriately authorized deployable artifacts in the repository; no persistent hosted storage is assumed. Cloud may override server security settings; local configuration is not a substitute for provider controls. The limits above are configuration bounds, not measured performance promises. Measure wall time, cache peak, termination and actual installation on the target deployment; if a valid curated analysis exceeds capacity, do not silently reduce its statistical semantics. Public launch remains blocked pending the operator's repository, connected account, applicable rights, provider verification and successful real-race browser proof.
